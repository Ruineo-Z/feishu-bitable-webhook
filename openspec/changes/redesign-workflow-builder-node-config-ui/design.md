## Context

当前工作流编辑器已具备基础可视化能力，但业务侧核心痛点仍集中在“节点配置效率与可理解性”上：

- 节点新增入口不统一，用户不清楚“可添加节点种类”与使用边界。
- 节点选中后的配置入口不稳定，容易出现“配置与画布割裂”的认知负担。
- 复杂流程在画布中的导航能力不足（平移/缩放/拖拽与连线可读性不足）。
- 视觉语义尚未统一到 Shadcn 组件体系，交互一致性与工程复用性不足。

本次变更不调整后端 workflow API 与执行引擎语义，重点是前端工作台结构、节点配置抽象与画布交互可用性。

## Goals / Non-Goals

**Goals:**

- 建立“左侧工作流列表 + 中间流程画布 + 节点选中后右侧配置面板”的稳定三段式编辑体验。
- 建立统一的节点目录（Node Catalog）与节点配置 schema（Node Config Schema），支持按类型动态渲染配置表单。
- 画布支持节点拖拽、画布平移、缩放，以及 if/else 分支的曲线连线展示。
- 统一采用 Shadcn 组件语义构建编辑器界面，提升一致性与开发效率。
- 保持与现有 DSL / API 契约兼容，确保“可视化编辑 -> DSL 提交”链路稳定。

**Non-Goals:**

- 不在本次改造 workflow 执行引擎、插件运行机制与字段 codec 行为。
- 不引入新的后端持久化模型或 API 版本。
- 不在本次实现完整跨项目模板市场，仅提供首期节点类型目录与默认配置。

## Decisions

### Decision 1：采用“节点注册表驱动”而非散落式配置表单

- **选择**：新增 Node Registry 抽象，统一维护节点元数据（类型、分类、默认值、校验规则、表单渲染配置、DSL 映射器）。
- **原因**：
  - 新增节点类型时无需重写整页逻辑，扩展成本低。
  - 可以在“添加节点弹层”和“右侧配置面板”复用同一份元数据。
  - 便于对接后续字段类型能力矩阵。
- **备选方案**：在页面中按 `if/else` 硬编码每个节点配置；短期快但长期维护成本高。

### Decision 2：右侧配置面板采用“选中态显隐”

- **选择**：默认不显示右侧面板；仅当节点被选中时显示对应配置，取消选中后隐藏。
- **原因**：
  - 降低非选中状态信息噪音，强化“画布导航优先”的主路径。
  - 与业务用户心智一致：先定位节点，再配置参数。
- **备选方案**：常驻面板 + 占位信息；虽然可减少布局抖动，但会增加视觉负担。

### Decision 3：画布交互采用“自研渲染层 + 可替换适配边界”

- **选择**：保留当前工程可控的画布实现路径，补齐 viewport（pan/zoom）与贝塞尔连线渲染；同时抽象 `CanvasAdapter` 接口，保留后续切换 React Flow 的低成本路径。
- **原因**：
  - 可在现有代码基础上快速收口并落地业务价值。
  - 通过适配边界降低未来迁移风险。
- **备选方案**：立即全面切换 React Flow；可获得成熟能力，但当前切换成本与样式重塑成本较高。

### Decision 4：连线规范采用“分支语义 + 贝塞尔曲线”

- **选择**：节点连线统一使用 cubic bezier 曲线；条件节点 `if/else` 分支通过标签和颜色语义区分。
- **原因**：
  - 曲线连线在密集节点场景下可读性更高，视觉更高级。
  - 分支语义明确，减少误配与误读。
- **备选方案**：直线/折线；实现简单，但在复杂图中观感与辨识度较弱。

### Decision 5：UI 组件体系统一到 Shadcn 语义

- **选择**：编辑器控制区、弹层、表单、标签、提示等统一采用 Shadcn 组件语义（Card/Tabs/Input/Select/Button/Badge/Sheet 等）。
- **原因**：
  - 组件语义一致，减少自定义样式分裂。
  - 与现有前端工程生态兼容，复用高。
- **备选方案**：混搭自定义组件与多套 UI 库；短期灵活，长期一致性差。

## Risks / Trade-offs

- **[Risk] 节点 schema 与后端 DSL 能力不一致** → **Mitigation**：在 adapter 层提供节点类型白名单与提交前 schema 校验，提交失败时回显字段级错误。
- **[Risk] 画布交互增强后性能下降** → **Mitigation**：限制重绘范围、使用 memoized 节点渲染、按需计算连线路径。
- **[Risk] 自研曲线连线交互细节不足** → **Mitigation**：定义 `CanvasAdapter` 抽象与接口契约，为后续切换 React Flow 预留实现位。
- **[Risk] 节点配置面板过于复杂影响上手** → **Mitigation**：按节点类型分组字段、提供默认值与必填提示、仅展示与当前类型相关配置。

## Migration Plan

1. 定义 Node Registry 与节点配置 schema（含默认值、校验、UI 元数据）。
2. 重构编辑器布局为三段式，接入节点选中态驱动的右侧面板显隐。
3. 实现“添加节点”弹层与节点分类列表，完成节点插入主流程。
4. 增强画布 viewport 能力（拖拽/平移/缩放）并替换连线为贝塞尔曲线。
5. 将节点配置结果统一映射为现有 DSL，接入创建/编辑提交链路。
6. 增加关键交互测试与适配器测试，完成验收与文档更新。

## Open Questions

- 首期节点目录是否固定为 `trigger / condition / action / end` 四大类，还是需要同步支持“子类型模板”（如 create/query/delete）快速入口？
- 条件节点分支展示是否需要支持自定义标签（不仅限于 `if/else`）？
- 何时触发 React Flow 迁移决策：以交互复杂度阈值还是性能指标阈值作为切换条件？
