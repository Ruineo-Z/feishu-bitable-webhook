## Why

当前新版工作流在事件处理时采用“加载全部启用工作流后逐个过滤”的方式，随着工作流数量增加会带来匹配性能下降与误触发风险。我们需要把“工作流与多维表格/数据表绑定”变为一等能力，让事件触发后可以快速、稳定地定位候选工作流。

## What Changes

- 引入工作流作用域（scope）模型，默认面向 `app_token + table_id` 的表级绑定。
- 将事件匹配流程调整为“先按作用域路由，再做条件判断与步骤执行”。
- 为工作流增加可索引的路由字段与查询路径，避免每次全量扫描所有 active workflows。
- 明确“全局工作流”语义：仅允许显式声明，不再依赖绑定字段缺失进行隐式全局匹配。
- 增加兼容迁移策略，确保历史工作流在升级期间行为可预期（如过渡期兼容、标记与告警）。

## Capabilities

### New Capabilities
- `workflow-scope-routing`: 定义工作流作用域绑定、事件路由键匹配、候选工作流快速检索与全局工作流显式声明规则。

### Modified Capabilities
- （无）

## Impact

- 受影响代码：`src/lark.ts`（事件→工作流路由入口）、`src/db/workflows.ts`（工作流查询路径）、`src/routes/workflow.ts`（工作流创建/更新接口约束）。
- 受影响数据模型：`workflows` 表可能增加作用域字段与索引（如 `scope_type`、`app_token`、`table_id`、复合索引）。
- 受影响 API 行为：工作流配置校验规则将更明确（默认要求绑定范围；全局模式需显式声明）。
- 运维影响：需要一次数据迁移与回填策略，用于平滑升级现有工作流。
