## Why

当前工作流主要通过接口与 Swagger 进行配置，配置门槛较高且容易出错，不利于业务侧快速创建与维护自动化流程。我们需要提供可视化管理页面，让工作流的新增、编辑、启停与删除在网页端可直接完成。

## What Changes

- 新增工作流管理 Web UI，提供工作流列表、创建、编辑、删除等核心能力。
- 在创建/编辑流程中提供结构化表单，支持配置基础信息、触发条件、执行步骤与作用域（table/global）。
- 在列表页提供状态与关键字段展示，支持快速识别工作流归属（如 app_token/table_id）与启用状态。
- 对前端提交参数做基础校验，并对后端错误响应提供可理解的提示与引导。
- 统一基于现有 `/api/workflows` 接口族进行交互，遵循当前响应 envelope（`code/message/data/meta`）。

## Capabilities

### New Capabilities
- `workflow-management-web-ui`: 提供面向运营/开发人员的工作流可视化管理界面，覆盖工作流的查询、创建、编辑、删除与状态管理。

### Modified Capabilities
- (无)

## Impact

- 受影响代码：新增前端页面与相关静态资源（路由、页面组件、请求封装、表单校验逻辑）。
- 受影响 API：复用现有 `workflows` 相关接口，可能补充前端友好字段与错误文案约定（不改变核心业务语义）。
- 受影响用户：业务配置人员可从“API/文档驱动”转为“页面驱动”进行工作流维护。
- 受影响运维：需要在本地开发与部署流程中支持前端页面资源加载与联调。
